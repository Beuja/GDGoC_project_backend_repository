# 시작하기 (개발 환경 세팅 · 확인 명령어)

처음 세팅하는 팀원이 위에서부터 순서대로 따라 하면 된다.
명령어는 프로젝트 루트(`GDG_1234/`)의 터미널에서 실행한다. IntelliJ에서는 하단 **Terminal** 탭을 쓰면 된다.

---

## 1. 처음 한 번만

### 1-1. 설치
- **Git**: https://git-scm.com
- **uv** (Python 버전과 패키지를 관리하는 도구. Python 3.12도 uv가 알아서 받는다)
  ```powershell
  # Windows (PowerShell)
  powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  ```
  ```bash
  # macOS / Linux
  curl -LsSf https://astral.sh/uv/install.sh | sh
  ```
  설치 후 **터미널(또는 IDE)을 다시 열어야** `uv` 명령이 인식된다.

### 1-2. Git 설정
```bash
git config --global user.name "GitHub 아이디 또는 이름"
git config --global user.email "GitHub 계정 이메일"
git config --global core.autocrlf input     # 줄바꿈 통일 (.gitattributes가 LF로 관리)
```

### 1-3. 코드 받기
```bash
# 처음이면
git clone https://github.com/Beuja/GDGoC_project_backend_repository.git
cd GDGoC_project_backend_repository

# 이미 받아 둔 저장소면
git switch main
git pull
```

### 1-4. 패키지 설치
```bash
uv sync
```
- 프로젝트 폴더에 `.venv`(프로젝트 전용 가상환경)가 생기고 Python 3.12와 패키지가 설치된다.
- `pip install`은 쓰지 않는다.

### 1-5. IDE 인터프리터 지정
- **IntelliJ**: File → Project Structure → SDK → Add SDK → Python SDK → **Existing** → `.venv\Scripts\python.exe` (macOS: `.venv/bin/python`)
- **VS Code**: `Ctrl+Shift+P` → Python: Select Interpreter → `.venv`

IDE 플러그인과 포맷 설정은 [협업가이드 2-1](협업가이드.md#2-1-ide-설정-맞추기-intellij--vs-code)을 따른다.

### 1-6. 서버 실행
```bash
uv run fastapi dev main.py
```
브라우저에서 http://127.0.0.1:8000/docs 를 열어 API 목록이 보이면 성공이다. 서버를 끌 때는 터미널에서 `Ctrl+C`를 누른다.

> 앞에 **`uv run`을 꼭 붙인다.** `fastapi dev`만 쓰면 전역 Python이 실행되어 에러가 나거나 버전이 달라질 수 있다.

## 2. 확인용 명령어

세팅이 맞는지 아래 명령어로 확인한다. 예상 결과와 다르면 3번 문제 해결을 본다.

| 확인할 것 | 명령어 | 정상 결과 |
|---|---|---|
| uv 설치 | `uv --version` | `uv 0.x.x` |
| 프로젝트 Python 버전 | `uv run python --version` | `Python 3.12.x` |
| 직접 추가한 패키지 | `uv tree --depth 1` | `fastapi[standard]` 한 줄 |
| FastAPI 설치 | `uv run python -c "import fastapi; print(fastapi.__version__)"` | 버전 숫자 출력 |
| 패키지가 lock과 일치하는지 | `uv sync --locked` | 에러 없이 끝남 |
| Git 사용자 | `git config user.name` / `git config user.email` | 내 이름 / 이메일 |
| 줄바꿈 설정 | `git config core.autocrlf` | `input` |
| 작업 폴더 상태 | `git status` | `nothing to commit, working tree clean` |
| 최신 main 반영 | `git fetch` 후 `git status` | `Your branch is up to date with 'origin/main'` |
| 서버 동작 | `uv run fastapi dev main.py` → http://127.0.0.1:8000/docs | Swagger 화면 |

> `uv tree`를 보면 패키지가 60개 정도로 많아 보인다. `fastapi[standard]`가 함께 설치하는 의존 패키지라서 **정상**이다.

## 3. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `uv` 명령을 찾을 수 없음 | 설치 후 터미널을 다시 안 엶 | 터미널 또는 IDE 재시작 |
| `To use the fastapi command, please install "fastapi[standard]"` | `uv run` 없이 전역 Python으로 실행 | `uv run fastapi dev main.py` |
| IDE에서 `Import "fastapi" could not be resolved` | IDE가 `.venv`가 아닌 다른 Python을 보고 있음 | 1-5대로 인터프리터를 `.venv`로 지정 |
| IDE가 "가상환경을 만들까요?"라고 물어봄 | 전역 설치를 감지한 IDE 안내 | 무시한다 (uv가 `.venv`를 관리) |
| `.venv`의 Python이 3.12가 아님 | 예전에 만든 `.venv`가 남아 있음 | `.venv` 폴더 삭제 후 `uv sync` |
| `Address already in use` / 포트 8000 사용 중 | 서버가 이미 켜져 있음 | 기존 터미널에서 `Ctrl+C`, 또는 `--port 8001` |
| `git pull` 시 `Please commit or stash them` | 커밋 안 된 변경이 있음 | `git status`로 확인 후 커밋하거나 `git restore <파일>`로 되돌림 |

## 4. 평소 작업 명령어

```bash
# 작업 시작 전: 최신 코드 + 패키지 반영
git switch main
git pull
uv sync                         # pull 후 uv.lock이 바뀌었을 수 있으므로 항상 실행

# 브랜치 만들고 작업
git switch -c feat/<도메인>-<내용>

# 서버 실행
uv run fastapi dev main.py

# 패키지 추가 / 제거 (pyproject.toml, uv.lock이 같이 바뀐다 → 같이 커밋)
uv add <패키지>
uv add --dev <패키지>           # 테스트·린트 등 개발용
uv remove <패키지>

# 커밋 & push
git add <파일>
git commit -m "feat: 설명"
git push -u origin <브랜치>     # 이후 GitHub에서 PR 생성
```

브랜치·커밋·PR 규칙은 [협업가이드](협업가이드.md)와 [`CLAUDE.md`](../CLAUDE.md)를 따른다.
